# 環境変数設定値の取得方法

## 概要

LINE Messaging APIのWebhook機能で使用する環境変数の実際の値を取得する方法を説明します。

---

## 📋 設定が必要な環境変数

| 環境変数名 | 説明 | 取得方法 |
|-----------|------|---------|
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Messaging APIのアクセストークン | LINE Developers Console |
| `LINE_CHANNEL_SECRET` | LINE Messaging APIのシークレット | LINE Developers Console |
| `ADMIN_ACCESS_KEYWORD` | 管理者用キーワード | 管理者が自由に設定 |
| `NEXT_PUBLIC_ADMIN_URL` | 管理画面のURL | AWS AmplifyのデプロイURL |

---

## 1. LINE_CHANNEL_ACCESS_TOKEN の取得

### 手順

1. [LINE Developers Console](https://developers.line.biz/console/) にアクセス
2. プロバイダーを選択（または新規作成）
3. Messaging APIチャネルを選択
4. 「Messaging API」タブを開く
5. 「チャネルアクセストークン」セクションを開く
6. 「発行」ボタンをクリック
7. 表示されたトークンをコピー

### 値の例

```
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

**注意**: 
- トークンは長い文字列です（通常100文字以上）
- トークンは一度しか表示されないため、必ずコピーしてください
- トークンが漏洩した場合は、再発行してください

---

## 2. LINE_CHANNEL_SECRET の取得

### 手順

1. [LINE Developers Console](https://developers.line.biz/console/) にアクセス
2. Messaging APIチャネルを選択
3. 「基本設定」タブを開く
4. 「チャネルシークレット」を確認
5. 「表示」ボタンをクリックしてシークレットを表示
6. 表示されたシークレットをコピー

### 値の例

```
1234567890abcdef1234567890abcdef
```

**注意**: 
- シークレットは32文字の16進数文字列です
- シークレットは機密情報のため、Gitにコミットしないでください

---

## 3. ADMIN_ACCESS_KEYWORD の設定

### 説明

管理者用キーワードは、LINE公式アカウントに送信するランダムな文字列です。一般の人が打つことはない、推測されにくい文字列を設定してください。

### 設定例

#### 推奨パターン1: ランダムな文字列

```
admin2024secret123xyz
```

#### 推奨パターン2: 日付とランダム文字列の組み合わせ

```
gacha-admin-2024-12-10-abc123
```

#### 推奨パターン3: UUID風の文字列

```
admin-a1b2c3d4-e5f6-7890-abcd-ef1234567890
```

### 注意事項

- **推測されにくい文字列を設定**: `admin` や `password` などは使用しない
- **長さ**: 10文字以上を推奨
- **文字種**: 英数字とハイフン、アンダースコアを使用可能
- **大文字小文字**: 区別されますが、実装では大文字小文字を区別せずに比較します

---

## 4. NEXT_PUBLIC_ADMIN_URL の設定

### AWS AmplifyのURLを確認

1. [AWS Amplify Console](https://console.aws.amazon.com/amplify/) にアクセス
2. アプリを選択
3. デプロイ完了後、URLが表示されます

### URLの形式

#### デフォルトURL（自動生成）

```
https://main.xxxxxxxxxxxx.amplifyapp.com/admin
```

**例**:
```
https://main.d2zlbom9902v0u.amplifyapp.com/admin
```

#### カスタムドメインを使用する場合

```
https://your-domain.com/admin
```

### 設定値の例

#### ローカル開発環境

```env
NEXT_PUBLIC_ADMIN_URL=http://localhost:3000/admin
```

#### 本番環境（AWS Amplify）

```env
NEXT_PUBLIC_ADMIN_URL=https://main.d2zlbom9902v0u.amplifyapp.com/admin
```

**注意**: 
- この環境変数はオプションです
- 設定しない場合、相対パス `/admin` が使用されます
- 本番環境では、フルURLを設定することを推奨します

---

## 📝 実際の設定例

### ローカル開発環境（`.env.local`）

```env
# LINE Messaging API
LINE_CHANNEL_ACCESS_TOKEN=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
LINE_CHANNEL_SECRET=1234567890abcdef1234567890abcdef

# 管理者用キーワード
ADMIN_ACCESS_KEYWORD=admin2024secret123xyz

# 管理画面URL
NEXT_PUBLIC_ADMIN_URL=http://localhost:3000/admin
```

### 本番環境（AWS Amplify Console）

AWS Amplify Consoleの「Environment variables」で以下を設定：

| キー | 値の例 |
|------|--------|
| `LINE_CHANNEL_ACCESS_TOKEN` | `xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` |
| `LINE_CHANNEL_SECRET` | `1234567890abcdef1234567890abcdef` |
| `ADMIN_ACCESS_KEYWORD` | `admin2024secret123xyz` |
| `NEXT_PUBLIC_ADMIN_URL` | `https://main.d2zlbom9902v0u.amplifyapp.com/admin` |

---

## ✅ 設定後の確認

### 1. 環境変数が正しく設定されているか確認

#### ローカル開発環境

```powershell
# .env.localファイルを確認
cat .env.local
```

#### 本番環境（AWS Amplify）

1. AWS Amplify Console → アプリ → Environment variables
2. 設定した環境変数が表示されているか確認

### 2. Webhook URLの設定

LINE Developers ConsoleでWebhook URLを設定：

1. [LINE Developers Console](https://developers.line.biz/console/) にアクセス
2. Messaging APIチャネルを選択
3. 「Messaging API」タブ → 「Webhook URL」→「編集」
4. Webhook URLを設定：
   - **ローカル開発**: `https://your-ngrok-url.ngrok.io/api/webhook/line`
   - **本番環境**: `https://main.d2zlbom9902v0u.amplifyapp.com/api/webhook/line`
5. 「Webhookの利用」を有効化
6. 「検証」をクリックして接続を確認

### 3. 動作確認

1. LINE公式アカウントを友だち追加
2. 管理者用キーワード（`ADMIN_ACCESS_KEYWORD`で設定した値）を送信
3. 管理画面URLが返信されることを確認

---

## 🔒 セキュリティ注意事項

1. **環境変数の保護**
   - `.env.local` はGitにコミットしない
   - `.gitignore` に `.env.local` が含まれているか確認

2. **トークンとシークレットの管理**
   - `LINE_CHANNEL_ACCESS_TOKEN` と `LINE_CHANNEL_SECRET` は機密情報
   - 漏洩した場合は、LINE Developers Consoleで再発行

3. **キーワードの管理**
   - `ADMIN_ACCESS_KEYWORD` は管理者のみが知っている必要があります
   - 定期的にキーワードを変更することを推奨
