## 概要

本番環境で必要なアカウントと設定をビジネスオーナーに作成していただく必要がある項目をまとめています。

**作業の流れ**:

1. ビジネスオーナーが各サービスのアカウントを作成
2. 必要な設定と情報を取得
3. 開発者に情報を安全に共有
4. 開発者が環境変数を設定してデプロイ

## 必須アカウント一覧

### 1. AWS アカウント（本番環境）

**作成者**: ビジネスオーナー  
**用途**: アプリケーションのホスティングとデータベース管理

#### ビジネスオーナーが行う作業

| 作業項目               | 説明                                                     | 詳細                                                       |
| ---------------------- | -------------------------------------------------------- | ---------------------------------------------------------- |
| **AWS アカウント作成** | AWS のルートアカウントを作成                             | [AWS 公式サイト](https://aws.amazon.com/jp/)で新規登録     |
| **IAM ユーザー作成**   | 開発者用の IAM ユーザーを作成                            | IAM コンソールで新規ユーザーを作成                         |
| **IAM 権限の付与**     | 開発者が必要な権限を付与                                 | 以下の権限ポリシーをアタッチ                               |
| **アクセスキーの発行** | IAM ユーザーのアクセスキーを発行                         | IAM コンソール → ユーザー → セキュリティ認証情報 → 作成    |
| **アクセスキーの共有** | 開発者にアクセスキー ID とシークレットアクセスキーを共有 | セキュアな方法で共有（後述の「情報の受け渡し方法」を参照） |

#### AWS アカウント作成手順（ビジネスオーナー向け）

1. **AWS 公式サイトにアクセス**

   - [AWS アカウント作成ページ](https://portal.aws.amazon.com/billing/signup)にアクセス

2. **アカウント情報の入力**

   - メールアドレス、パスワード、AWS アカウント名を入力
   - メールアドレスは、アカウントのルートユーザーとして使用されます

3. **連絡先情報の入力**

   - 氏名、住所、電話番号などの連絡先情報を入力
   - 住所は英語表記で入力してください

4. **支払い情報の入力**

   - 有効なクレジットカードまたはデビットカードの情報を入力
   - AWS の利用料金は、入力した支払い方法に請求されます

5. **本人確認**

   - 入力した電話番号に SMS または音声通話で確認コードが送信されます
   - 受信した確認コードを入力して、本人確認を完了します

6. **サポートプランの選択**
   - 必要に応じて、AWS のサポートプランを選択します
   - 基本的な利用であれば、無料の「ベーシックサポート」を選択してください

**参考資料**: [プロが教える AWS アカウント作成方法 ～ルートユーザアカウント作成編～](https://www.cloudsolution.tokai-com.co.jp/white-paper/2021/0604-238.html)

#### IAM ユーザー作成手順（ビジネスオーナー向け）

1. **AWS コンソールにログイン**（ルートユーザーで）

   - [AWS マネジメントコンソール](https://console.aws.amazon.com/)にアクセス
   - ルートユーザーでログイン

2. **IAM コンソールを開く**

   - 検索バーで「IAM」を検索
   - IAM コンソールを開く

3. **ユーザーを作成**

   - 左メニュー → 「ユーザー」→「ユーザーを追加」
   - ユーザー名: `gacha-lab-developer`（任意）

4. **アクセスの種類を選択**

   - 「AWS マネジメントコンソールへのアクセス」にチェック（オプション）
   - 「プログラムによるアクセス」にチェック（必須）
   - コンソールアクセスを有効にする場合は、パスワードを設定

5. **権限を付与**

   - 「既存のポリシーを直接アタッチ」を選択
   - ⚠️ **重要**: 本番環境では、開発作業を効率的に進めるため、**最大の権限（AdministratorAccess）を付与**します
   - `AdministratorAccess` ポリシーを選択
     - このポリシーは、AWS アカウント内のすべてのリソースに対する完全なアクセス権限を付与します
     - セキュリティ上のリスクがあるため、信頼できる開発者のみに付与してください

6. **タグの追加（オプション）**

   - 必要に応じて、ユーザーにタグを追加できます

7. **ユーザーの作成を確認**

   - 設定内容を確認して、「ユーザーの作成」をクリック

8. **アクセスキーを保存**

   - アクセスキー ID とシークレットアクセスキーが表示されます
   - ⚠️ **重要**: シークレットアクセスキーは**この時点でしか表示されません**
   - アクセスキー ID とシークレットアクセスキーを**必ず保存**してください
   - CSV ファイルとしてダウンロードすることも可能です

9. **開発者に共有**
   - セキュアな方法でアクセスキーを共有（後述の「情報の受け渡し方法」を参照）

**参考資料**: [AWS IAM ユーザー作成手順](https://blog.serverworks.co.jp/2022/01/07/180000)

**⚠️ 重要な注意事項**:

- 本ドキュメントでは、開発作業を効率的に進めるため、**最大の権限（AdministratorAccess）を付与**することを前提としています
- これは、AWS アカウント内のすべてのリソースに対する完全なアクセス権限を意味します
- セキュリティ上のリスクがあるため、**信頼できる開発者のみに付与**してください
- より厳格なセキュリティが必要な場合は、必要最小限の権限のみを付与することを検討してください

#### 最大権限（AdministratorAccess）によるセキュリティ上の懸念事項

**AdministratorAccess** を付与することで、以下のような操作が可能になります。これらは重大なセキュリティリスクを伴うため、十分に注意してください：

| リスク項目                 | 説明                                                       | 影響                                 |
| -------------------------- | ---------------------------------------------------------- | ------------------------------------ |
| **アカウントの削除**       | AWS アカウント自体を削除できる                             | すべてのリソースとデータが失われる   |
| **課金の増加**             | 無制限にリソースを作成・使用できる                         | 予想外の高額な請求が発生する可能性   |
| **データの削除**           | すべてのデータベース、S3 バケット、ファイルを削除できる    | 復旧不可能なデータ損失               |
| **セキュリティ設定の変更** | セキュリティグループ、IAM ポリシー、暗号化設定を変更できる | セキュリティホールが発生する可能性   |
| **アクセスキーの作成**     | 新しい IAM ユーザーやアクセスキーを作成できる              | 不正アクセスのリスク                 |
| **ログの削除**             | CloudTrail や CloudWatch のログを削除できる                | 監査証跡が失われる                   |
| **バックアップの削除**     | RDS スナップショットや S3 バケットのバージョンを削除できる | データ復旧が不可能になる             |
| **ネットワーク設定の変更** | VPC、サブネット、ルートテーブルを変更できる                | サービスが停止する可能性             |
| **暗号化キーの削除**       | KMS キーを削除できる                                       | 暗号化されたデータが復号できなくなる |
| **請求情報の変更**         | 請求先情報や支払い方法を変更できる                         | 不正な請求が発生する可能性           |

**推奨される対策**:

1. **定期的な監査**: CloudTrail で IAM ユーザーの操作を監視
2. **アクセスキーのローテーション**: 定期的にアクセスキーを更新
3. **MFA（多要素認証）の有効化**: コンソールアクセスに MFA を設定
4. **予算アラートの設定**: AWS Budgets で予算アラートを設定
5. **リソースタグの活用**: 作成されたリソースにタグを付与して管理
6. **定期的な権限の見直し**: 必要最小限の権限に変更することを検討

#### 開発者が行う作業（概要）

開発者は、ビジネスオーナーから提供された IAM ユーザーのアクセスキーを使用して、以下の作業を実行します：

- **AWS Amplify**: アプリケーションのデプロイ先を作成
- **AWS RDS (PostgreSQL)**: データベースサーバーを作成
- **AWS S3**: 動画・画像の保存先となるバケットを作成
- **AWS CloudFront**: CDN（コンテンツ配信）のディストリビューションを作成
- **セキュリティグループ**: データベースへのアクセス制御を設定
- **環境変数の設定**: AWS Amplify Console で環境変数を設定（後述の環境変数一覧を参照）

#### 注意事項

- ⚠️ **AWS アカウントは有料サービス**です（無料枠あり）
- ⚠️ **RDS は使用量に応じて課金**されます
- ⚠️ **ルートユーザーは通常使用しない**（セキュリティのため）
- ⚠️ **IAM ユーザーのアクセスキーは厳重に管理**する
- ⚠️ **定期的にアクセスキーをローテーション**することを推奨
- ⚠️ **セキュリティグループの設定**で Amplify からの接続を許可する必要があります

### 3. Stripe アカウント（本番環境）

**作成者**: ビジネスオーナー  
**用途**: 決済処理（PayPay、クレジットカードなど）

#### 必要な設定項目

| 項目                       | 説明                        | 取得方法                                             |
| -------------------------- | --------------------------- | ---------------------------------------------------- |
| **Stripe アカウント**      | Stripe のビジネスアカウント | [Stripe 公式サイト](https://stripe.com/jp)で新規登録 |
| **本番 API キー**          | 本番環境用の API キー       | Stripe ダッシュボード → 開発者 → API キー            |
| **Webhook エンドポイント** | 決済完了通知の受信先        | Stripe ダッシュボード → 開発者 → Webhook             |
| **ビジネス情報**           | 会社情報、銀行口座情報      | Stripe ダッシュボード → 設定 → ビジネス情報          |

#### 必要な手続き

1. **アカウント作成**: メールアドレスで登録
2. **ビジネス情報の登録**:
   - 会社名
   - 住所
   - 電話番号
   - 事業内容
3. **銀行口座の登録**: 入金先の銀行口座情報
4. **本人確認**: 身分証明書の提出（必要に応じて）
5. **本番モードへの切り替え**: テストモードから本番モードへ

#### 注意事項

- ⚠️ **本番モードでは実際の決済が発生**します
- ⚠️ **手数料が発生**します（Stripe の手数料体系を確認）
- ⚠️ **銀行口座情報の登録**が必要です（入金先）
- ⚠️ **ビジネス情報の審査**が必要な場合があります

### 4. LINE Developers アカウント（本番環境）

**作成者**: ビジネスオーナー  
**用途**: LINE 公式アカウントと LINE ミニアプリの管理

#### 必要な設定項目

| 項目                           | 説明                         | 取得方法                                                                  |
| ------------------------------ | ---------------------------- | ------------------------------------------------------------------------- |
| **LINE Developers アカウント** | LINE Developers のアカウント | [LINE Developers Console](https://developers.line.biz/console/)で新規登録 |
| **プロバイダー**               | 開発者組織                   | LINE Developers Console で作成                                            |
| **Messaging API チャネル**     | LINE 公式アカウントとの連携  | LINE Official Account Manager から作成                                    |
| **LINE ミニアプリ**            | LINE 内で動作するアプリ      | LINE Developers Console で「LINE ミニアプリ」チャネルを作成               |

#### 開発者への権限付与について

**プロバイダーのメンバー招待**:

ビジネスオーナーが LINE Developers Console でプロバイダーを作成した後、開発者をメンバーとして招待することができます。

**権限レベル**:

| 権限レベル          | 説明                                       | 可能な操作                                                                 |
| ------------------- | ------------------------------------------ | -------------------------------------------------------------------------- |
| **オーナー**        | プロバイダーの作成者（最初に作成した人）   | すべての操作が可能（プロバイダーの削除、アカウント譲渡なども含む）         |
| **管理者（Admin）** | オーナーから招待された管理者               | オーナーとほぼ同等の操作が可能（チャネル作成・設定変更、メンバー招待など） |
| **メンバー**        | オーナーまたは管理者から招待されたメンバー | チャネルの設定変更など、一部の操作に制限                                   |

**Admin 権限で可能な操作**:

- ✅ チャネルの作成・削除
- ✅ チャネルの設定変更（エンドポイント URL、Webhook URL など）
- ✅ メンバーの招待・削除
- ✅ チャネルアクセストークンの再発行
- ✅ チャネルシークレットの確認
- ✅ LINE ミニアプリの設定変更

**Admin 権限ではできない操作（オーナーのみ）**:

- ❌ プロバイダーの削除
- ❌ プロバイダーの譲渡
- ❌ オーナー権限の変更

**推奨事項**:

- 開発作業を効率的に進めるため、開発者には**管理者（Admin）権限**を付与することを推奨します
- Admin 権限があれば、チャネルの設定変更やエンドポイント URL の更新など、開発に必要な操作をすべて実行できます
- セキュリティ上の懸念がある場合は、必要最小限の権限（メンバー）を付与することも可能です

#### 注意事項

- ⚠️ **LINE 公式アカウントの作成**が必要です（別途手続き）
- ⚠️ **LINE ミニアプリのエンドポイント URL**を本番環境の URL に設定する必要があります
- ⚠️ **Webhook URL の設定**が必要です
- ⚠️ **開発者をメンバーとして招待する場合**、Admin 権限を付与することで、オーナーとほぼ同等の操作が可能になります

## 開発者に渡す情報一覧

ビジネスオーナーが各アカウントを作成・設定した後、開発者に以下の情報を安全に共有してください。

### 📋 情報共有チェックリスト

#### AWS 関連

- [ ] **AWS アカウント ID**（12 桁の数字）
- [ ] **IAM ユーザー名**（例: `gacha-lab-developer`）
- [ ] **アクセスキー ID**（`AKIAxxxxxxxxxxxxxxxx`）
- [ ] **シークレットアクセスキー**（`xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`）
- [ ] **リージョン**（`ap-northeast-1`（東京）を推奨）

#### Stripe 関連

- [ ] **公開可能キー（Publishable Key）**（`pk_live_xxxxxxxxxxxxx`）
- [ ] **シークレットキー（Secret Key）**（`sk_live_xxxxxxxxxxxxx`）
- [ ] **Webhook 署名シークレット**（`whsec_xxxxxxxxxxxxx`）

#### LINE 関連

- [ ] **チャネルアクセストークン**（`xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`）
- [ ] **チャネルシークレット**（`1234567890abcdef1234567890abcdef`）
- [ ] **LINE ミニアプリ ID**（`2008642684-xxxxxxxx`）

#### GitHub 関連

- [ ] **リポジトリ URL**（`https://github.com/your-org/gacha-lab`）
- [ ] **ブランチ名**（`main` または `master`）
- [ ] **開発者へのアクセス権限**（Read/Write または Admin）

### 🔐 情報の受け渡し方法

**重要**: 以下の情報は機密情報のため、安全な方法で共有してください。

#### 推奨方法

1. **パスワードマネージャーを使用**

   - 1Password、LastPass、Bitwarden など
   - 共有フォルダを作成して開発者にアクセス権限を付与

2. **暗号化されたファイルを共有**

   - 情報を Excel やテキストファイルにまとめる
   - パスワードで保護された ZIP ファイルを作成
   - パスワードは別のチャネル（電話、メッセージアプリなど）で共有

3. **セキュアなチャットツールを使用**
   - Slack、Microsoft Teams などのエンタープライズ向けツール
   - 機密情報チャンネルを作成して共有

#### 避けるべき方法

- ❌ **通常のメール**（暗号化されていない）
- ❌ **SNS の DM**（セキュリティが不十分）
- ❌ **チャットアプリの通常メッセージ**（暗号化されていない）

## 重要な注意事項

### セキュリティ

1. **環境変数は絶対に GitHub にコミットしない**
2. **API キーやシークレットは厳重に管理**
3. **AWS アカウントのアクセス権限を適切に設定**
   - ルートユーザーは通常使用しない
   - IAM ユーザーに必要最小限の権限のみを付与
   - 定期的にアクセスキーをローテーション
4. **データベースのパスワードは強力なものを使用**（32 文字以上推奨）
5. **IAM ユーザーのアクセスキーは漏洩しないよう注意**

### 本番環境への移行

1. **テスト環境で十分にテスト**してから本番環境へ
2. **バックアップ**を定期的に取得
3. **監視とログ**を設定
4. **エラー通知**を設定

### 法的要件

1. **個人情報保護法**への対応
2. **特定商取引法**への対応（決済サービス提供時）
3. **利用規約**と**プライバシーポリシー**の作成
4. **Cookie 同意**の取得（必要に応じて）
