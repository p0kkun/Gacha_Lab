# ローカルS3検証環境のセットアップ（LocalStack）

## 📋 概要

LocalStackを使用して、ローカル環境でS3へのアップロードとCloudFrontのテストをAWSと同じように検証できます。

**LocalStackとは**: AWSサービスのローカルエミュレーション環境です。S3、Lambda、DynamoDBなどのAWSサービスをローカルで実行できます。

---

## 🎯 メリット

- ✅ **コストなし**: AWSの料金がかからない
- ✅ **高速**: ローカル環境なので高速
- ✅ **オフライン**: インターネット接続不要
- ✅ **テスト容易**: 開発中のテストが簡単
- ✅ **データ永続化**: ローカルにデータが保存される

---

## 📦 前提条件

- Docker Desktop がインストールされていること
- Docker Compose が利用可能であること

---

## 🚀 セットアップ手順

### ステップ0: Docker Desktopの起動確認

**重要**: LocalStackを使用するには、Docker Desktopが起動している必要があります。

1. **Docker Desktopを起動**
   - Windows: スタートメニューから「Docker Desktop」を起動
   - タスクバーのDockerアイコンが緑色になるまで待つ（通常30秒〜1分）

2. **Dockerの動作確認**
   ```powershell
   docker ps
   ```
   
   正常に動作している場合、以下のような出力が表示されます（エラーが出ない）：
   ```
   CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES
   ```

3. **エラーが出る場合**
   - Docker Desktopが完全に起動するまで待つ
   - Docker Desktopを再起動
   - PCを再起動

### ステップ1: LocalStackの起動

#### 方法1: Docker Composeを使用（推奨）

```bash
# LocalStackコンテナを起動
docker-compose -f docker-compose.localstack.yml up -d

# 起動確認
docker ps | grep localstack
```

#### 方法2: 手動でDockerコンテナを起動

```bash
docker run -d \
  --name gacha-lab-localstack \
  -p 4566:4566 \
  -e SERVICES=s3 \
  -e DEBUG=1 \
  -e DATA_DIR=/tmp/localstack/data \
  -v "./localstack-data:/tmp/localstack" \
  localstack/localstack:latest
```

### ステップ2: S3バケットの作成

#### 方法1: セットアップスクリプトを使用（推奨）

**Windows (PowerShell)**:
```powershell
.\scripts\setup-localstack.ps1
```

**Linux/Mac**:
```bash
chmod +x scripts/setup-localstack.sh
./scripts/setup-localstack.sh
```

#### 方法2: AWS CLIを使用（手動）

```bash
# AWS CLIでLocalStackのS3にバケットを作成
aws --endpoint-url=http://127.0.0.1:4566 s3 mb s3://gacha-lab-test
```

**注意**: AWS CLIがインストールされていない場合は、以下のコマンドでインストールできます：

**Windows (winget)**:
```powershell
winget install Amazon.AWSCLI
```

**Mac (Homebrew)**:
```bash
brew install awscli
```

### ステップ3: 環境変数の設定

`.env.local`ファイルに以下を追加または更新：

```env
# LocalStackを使用する場合
USE_LOCALSTACK=true
LOCALSTACK_ENDPOINT=http://127.0.0.1:4566
LOCALSTACK_BASE_URL=http://127.0.0.1:4566

# S3設定（LocalStack用）
AWS_REGION=ap-northeast-1
AWS_ACCESS_KEY_ID=test  # LocalStackでは任意の値でOK
AWS_SECRET_ACCESS_KEY=test  # LocalStackでは任意の値でOK
AWS_S3_BUCKET_NAME=gacha-lab-test  # ステップ2で作成したバケット名

# CloudFrontはLocalStackでは使用しない（オプション）
# AWS_CLOUDFRONT_DOMAIN=
```

**重要**: `USE_LOCALSTACK=true` を設定すると、LocalStackが使用されます。

### ステップ4: 開発サーバーの起動

```bash
npm run dev
```

## 🧪 テスト方法

### 1. 管理画面から動画をアップロード

1. ブラウザで `http://localhost:3000/admin` にアクセス
2. 「動画管理」メニューを選択
3. 「+ 動画をアップロード」ボタンをクリック
4. 動画ファイルを選択してアップロード
5. アップロードが成功することを確認

### 2. LocalStackのS3バケットを確認

#### 方法1: AWS CLIを使用

```bash
# バケット内のファイル一覧を表示
aws --endpoint-url=http://127.0.0.1:4566 s3 ls s3://gacha-lab-test --recursive

# 特定のファイルをダウンロード
aws --endpoint-url=http://127.0.0.1:4566 s3 cp s3://gacha-lab-test/videos/common/xxx.mp4 ./test-download.mp4
```

#### 方法2: LocalStack Web UIを使用（オプション）

LocalStack Pro版ではWeb UIが利用できますが、Community版では利用できません。

### 3. アップロードしたファイルにアクセス

アップロードしたファイルは以下のURLでアクセスできます：

```
http://127.0.0.1:4566/gacha-lab-test/videos/common/[ファイル名]
```

または、管理画面の動画一覧で表示されるURLをクリックして確認できます。

## 🔄 AWSとLocalStackの切り替え

### LocalStackを使用する場合

`.env.local`:
```env
USE_LOCALSTACK=true
AWS_S3_BUCKET_NAME=gacha-lab-test
```

### 実際のAWSを使用する場合

`.env.local`:
```env
USE_LOCALSTACK=false
# または USE_LOCALSTACK を削除
AWS_ACCESS_KEY_ID=[実際のアクセスキーID]
AWS_SECRET_ACCESS_KEY=[実際のシークレットアクセスキー]
AWS_S3_BUCKET_NAME=gacha-lab-test
AWS_CLOUDFRONT_DOMAIN=[CloudFrontドメイン]  # オプション
```

## 🔧 トラブルシューティング

### エラー: "unable to get image" または "The system cannot find the file specified"

**原因**: Docker Desktopが起動していない、またはDockerデーモンに接続できません。

**解決方法**:

1. **Docker Desktopを起動**
   - Windows: スタートメニューから「Docker Desktop」を起動
   - Docker Desktopが起動するまで待つ（通常30秒〜1分）

2. **Docker Desktopの起動確認**
   ```powershell
   # Dockerが正常に動作しているか確認
   docker ps
   ```
   
   正常に動作している場合、以下のような出力が表示されます：
   ```
   CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES
   ```

3. **Docker Desktopの再起動**
   - Docker Desktopを完全に終了
   - 再度起動
   - 起動完了を待つ

4. **Docker Desktopがインストールされていない場合**
   - [Docker Desktop for Windows](https://www.docker.com/products/docker-desktop/) をダウンロード・インストール
   - インストール後、PCを再起動

### エラー: "Connection refused"

- LocalStackが起動しているか確認: `docker ps | grep localstack`
- LocalStackのログを確認: `docker logs gacha-lab-localstack`
- ポート4566が使用可能か確認

### エラー: "Bucket not found"

- バケットが作成されているか確認:
  ```bash
  aws --endpoint-url=http://127.0.0.1:4566 s3 ls
  ```
- バケットを作成:
  ```bash
  aws --endpoint-url=http://127.0.0.1:4566 s3 mb s3://gacha-lab-test
  ```

### エラー: "Invalid credentials"

- LocalStackでは任意の認証情報でOKです
- `.env.local`で `AWS_ACCESS_KEY_ID=test` と `AWS_SECRET_ACCESS_KEY=test` を設定してください

### ファイルが表示されない

- LocalStackのデータが永続化されているか確認
- `localstack-data/` ディレクトリの内容を確認
- LocalStackを再起動してみる

## 📊 LocalStackとAWSの違い

| 項目 | LocalStack | AWS |
|------|-----------|-----|
| **エンドポイント** | `http://localhost:4566` | `https://s3.ap-northeast-1.amazonaws.com` |
| **認証情報** | 任意の値でOK | 実際のIAM認証情報が必要 |
| **CloudFront** | エミュレーション不可 | 利用可能 |
| **コスト** | 無料 | 有料 |
| **パフォーマンス** | 高速（ローカル） | ネットワーク依存 |
| **データ永続化** | ローカルディレクトリ | S3バケット |

## 💡 補足: CloudFrontのローカル検証について

**注意**: LocalStackではCloudFrontの完全なエミュレーションは提供されていません。

ローカルでのCloudFront検証は以下の方法があります：

1. **URL生成のテスト**: CloudFront URLの生成ロジックをテスト
2. **実際のAWS CloudFrontを使用**: 開発環境のCloudFrontディストリビューションを使用
3. **モックサーバー**: 簡単なHTTPサーバーでCloudFrontを模擬

現在の実装では、LocalStack使用時は直接S3のURLを返すため、CloudFrontの動作確認は実際のAWS環境で行うことを推奨します。
