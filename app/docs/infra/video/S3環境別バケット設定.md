# S3 環境別バケット設定ガイド

## 📋 概要

開発環境と本番環境で異なるS3バケットを使用するための設定方法です。

**推奨構成**:
- **開発環境**: `gacha-lab-test` または `gacha-lab-dev`
- **本番環境**: `gacha-lab-prod` または `gacha-lab-production`

---

## 🎯 環境別バケットのメリット

1. **データの分離**: 開発と本番のデータを完全に分離
2. **セキュリティ**: 本番データへの誤操作を防止
3. **コスト管理**: 環境ごとのコストを把握しやすい
4. **アクセス制御**: 環境ごとに異なるIAMポリシーを適用可能

---

## 📝 設定手順

### ステップ1: 開発環境用バケットの作成

1. AWSコンソールでS3バケットを作成
   - **バケット名**: `gacha-lab-test`（または `gacha-lab-dev`）
   - **リージョン**: `ap-northeast-1`
   - その他の設定は [`AWS_S3動画アップロード設定手順.md`](./AWS_S3動画アップロード設定手順.md) を参照

### ステップ2: 本番環境用バケットの作成

1. AWSコンソールでS3バケットを作成
   - **バケット名**: `gacha-lab-prod`（または `gacha-lab-production`）
   - **リージョン**: `ap-northeast-1`
   - その他の設定は開発環境と同じ

### ステップ3: IAMユーザー/ポリシーの設定

#### オプション1: 同じIAMユーザーを使用（推奨）

開発環境と本番環境の両方のバケットにアクセスできるIAMポリシーを作成：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::gacha-lab-test",
        "arn:aws:s3:::gacha-lab-test/*",
        "arn:aws:s3:::gacha-lab-prod",
        "arn:aws:s3:::gacha-lab-prod/*"
      ]
    }
  ]
}
```

#### オプション2: 環境ごとに異なるIAMユーザーを使用

- 開発環境用IAMユーザー: `gacha-lab-s3-dev`
- 本番環境用IAMユーザー: `gacha-lab-s3-prod`

それぞれのバケットにのみアクセスできるポリシーを設定。

---

## 🔧 環境変数の設定

### ローカル開発環境（`.env.local`）

```env
# AWS S3設定（開発環境用）
AWS_REGION=ap-northeast-1
AWS_ACCESS_KEY_ID=[開発環境用のアクセスキーID]
AWS_SECRET_ACCESS_KEY=[開発環境用のシークレットアクセスキー]
AWS_S3_BUCKET_NAME=gacha-lab-test  # 開発環境のバケット名
AWS_CLOUDFRONT_DOMAIN=[開発環境のCloudFrontドメイン]  # オプション
```

### 本番環境（AWS Amplify の環境変数）

AWS Amplify Console → アプリ → Environment variables で設定：

```env
AWS_REGION=ap-northeast-1
AWS_ACCESS_KEY_ID=[本番環境用のアクセスキーID]
AWS_SECRET_ACCESS_KEY=[本番環境用のシークレットアクセスキー]
AWS_S3_BUCKET_NAME=gacha-lab-prod  # 本番環境のバケット名
AWS_CLOUDFRONT_DOMAIN=[本番環境のCloudFrontドメイン]  # オプション
```

### 本番環境（`.env.production.local` - ローカルからビルドする場合）

プロジェクトのルートディレクトリに`.env.production.local`ファイルを作成：

```env
# AWS S3設定（本番環境用）
AWS_REGION=ap-northeast-1
AWS_ACCESS_KEY_ID=[本番環境用のアクセスキーID]
AWS_SECRET_ACCESS_KEY=[本番環境用のシークレットアクセスキー]
AWS_S3_BUCKET_NAME=gacha-lab-prod  # 本番環境のバケット名
AWS_CLOUDFRONT_DOMAIN=[本番環境のCloudFrontドメイン]  # オプション
```

**重要**: `.env.production.local`は`.gitignore`に含まれていることを確認してください。

## 📊 環境別設定の比較表

| 項目 | 開発環境 | 本番環境 |
|------|---------|---------|
| **バケット名** | `gacha-lab-test` | `gacha-lab-prod` |
| **環境変数ファイル** | `.env.local` | AWS Amplify環境変数 または `.env.production.local` |
| **CloudFront** | 開発用ディストリビューション | 本番用ディストリビューション |
| **IAMユーザー** | 開発用（または共通） | 本番用（または共通） |

---

## 🔄 環境変数の優先順位（Next.js）

Next.jsでは、以下の順序で環境変数が読み込まれます：

1. `.env.production.local`（本番環境のみ、Gitにコミットしない）
2. `.env.local`（すべての環境、Gitにコミットしない）
3. `.env.production`（本番環境のみ、Gitにコミット可能）
4. `.env.development`（開発環境のみ、Gitにコミット可能）
5. `.env`（すべての環境、Gitにコミット可能）

**デプロイ環境（AWS Amplify）の場合**:
- Amplify Consoleで設定した環境変数が最優先で使用されます
