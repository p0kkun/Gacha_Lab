# 413エラー（リクエストサイズ制限）の対処法

## 🔴 問題の状況

動画アップロード時に **413 Content Too Large** エラーが発生します。

```
POST /api/admin/videos/upload 413 (Content Too Large)
content-length: 4794820 (約4.8MB)
```

## 🎯 原因

AWS AmplifyとNext.jsには、デフォルトでリクエストボディサイズの制限があります：

1. **AWS Amplify**: デフォルトで約4MBの制限
2. **Next.js API Routes**: デフォルトで約4.5MBの制限
3. **CloudFront**: デフォルトで約20MBの制限（ただし、Amplifyの制限が先に適用される）

## ✅ 解決策: Presigned URL方式を実装（実装済み）

**Presigned URL方式**を実装することで、Amplifyのリクエストサイズ制限を完全に回避できます。

### 実装内容

1. **Presigned URL生成API** (`/api/admin/videos/presigned-url`)
   - 動画アップロード用のPresigned URLを生成
   - ファイル情報（名前、タイプ、サイズ）を検証

2. **直接S3アップロード**
   - フロントエンドがPresigned URLを使って直接S3にアップロード
   - Amplifyのリクエストサイズ制限を回避

3. **DB登録API** (`/api/admin/videos/register`)
   - S3へのアップロード完了後、DBに動画情報を登録

### アップロードフロー

```
1. フロントエンド → Presigned URL生成API（小さいリクエスト）
2. フロントエンド → S3（直接アップロード、大きなファイル）
3. フロントエンド → DB登録API（小さいリクエスト）
```

### 利点

- ✅ Amplifyのリクエストサイズ制限を回避
- ✅ より大きなファイル（100MB以上）に対応可能
- ✅ サーバーの負荷を軽減（ファイルは直接S3に送信）
- ✅ アップロードの進捗を追跡可能（将来的な拡張）

### 旧実装（参考）

以前は、サーバー経由でファイルをアップロードしていましたが、Amplifyのリクエストサイズ制限により大きなファイルがアップロードできませんでした。

**旧実装の問題点**:
- サーバー経由でファイルをアップロード
- Amplifyのリクエストサイズ制限（約4MB）に引っかかる
- 大きなファイル（4.8MB以上）がアップロードできない

**新実装（Presigned URL方式）**:
- フロントエンドが直接S3にアップロード
- Amplifyのリクエストサイズ制限を回避
- より大きなファイル（100MB以上）に対応可能

## 📋 確認手順

### 1. デプロイ後の確認

1. 変更をコミット・プッシュ
2. AWS Amplifyでビルドが成功するか確認
3. 動画アップロードを再試行
4. ブラウザのNetworkタブで以下を確認：
   - `/api/admin/videos/presigned-url` リクエストが成功（200）
   - S3への直接アップロードが成功（200）
   - `/api/admin/videos/register` リクエストが成功（200）

### 2. エラーログの確認

まだエラーが発生する場合：

1. **ブラウザのコンソール**でエラーを確認
2. **Networkタブ**で各リクエストのステータスコードを確認：
   - Presigned URL生成: 401（認証エラー）または400（バリデーションエラー）
   - S3アップロード: 403（権限エラー）またはその他のエラー
   - DB登録: 500（サーバーエラー）またはその他のエラー
3. **CloudWatchログ**を確認（サーバーサイドエラーの場合）

### 3. トラブルシューティング

#### Presigned URL生成エラー

- **401 Unauthorized**: 認証トークンが無効
- **400 Bad Request**: ファイル情報のバリデーションエラー
- **500 Internal Server Error**: サーバーサイドエラー（CloudWatchログを確認）

#### S3アップロードエラー

- **403 Forbidden**: Presigned URLの権限エラー（IAM設定を確認）
- **400 Bad Request**: リクエスト形式エラー
- **その他のエラー**: S3バケットの設定を確認

#### DB登録エラー

- **401 Unauthorized**: 認証トークンが無効
- **400 Bad Request**: リクエストパラメータのバリデーションエラー
- **500 Internal Server Error**: サーバーサイドエラー（CloudWatchログを確認）

## ⚠️ 注意事項

### ファイルサイズの推奨値

- **動画ファイル**: 100MB以下を推奨
- **画像ファイル**: 10MB以下を推奨

### タイムアウトの考慮

大きなファイルのアップロードには時間がかかるため：

- フロントエンドでプログレスバーを表示
- タイムアウトエラーを適切に処理
- 必要に応じて `maxDuration` を調整

### セキュリティ

- ファイルタイプの検証を必ず実施
- ファイルサイズの上限を設定
- 認証チェックを必ず実施
